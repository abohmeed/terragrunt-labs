# 05.1 completed notes

`check.sh` is the same script as `start/check.sh`. A passing run ends with:

```text
PASS  05.1 remote state
```

`root.hcl` holds `terraform_binary` and the local `remote_state` block. Each unit includes that file.

| Unit | State file, next to `root.hcl` | `prefix` |
| --- | --- | --- |
| `dev` | `state/dev/terraform.tfstate` | `dev-lab` |
| `prod` | `state/prod/terraform.tfstate` | `prod-lab` |

`terragrunt render` in `dev/` includes:

```hcl
remote_state {
  backend = "local"
  config = {
    path = "<absolute path to this directory>/state/dev/terraform.tfstate"
  }
}
```

The working copy contains `backend.tf`, generated by Terragrunt, with that same path.

What the checker shows:

1. `terragrunt hcl fmt --check` passes.
2. `terragrunt run -- version` prints `Terraform v1.17.<patch>`. The unit files have no `terraform_binary` assignment.
3. Each plan is `3 to add`.
4. After apply, the state file is `state/<unit>/terraform.tfstate`. The resource state is not inside `.terragrunt-cache`.
5. Deleting `.terragrunt-cache` and running `terragrunt output` still prints `environment`, `prefix`, `note = "local remote state"`, and `name = "<prefix>-<word>-<word>"`.
6. Prod's apply leaves dev's `prefix` of `dev-lab` in `state/dev/terraform.tfstate`.
7. Destroy removes the resources. The marker file lives in the working copy, so once `.terragrunt-cache` is gone that file is already gone, and destroy removes the `random_pet` and the `null_resource`. The script then deletes the `state/` directory. `*.tfstate` is gitignored either way.

Lecture 05.2 uses this same block with `backend = "s3"`.
