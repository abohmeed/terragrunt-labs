# 05.1 Remote state

Configure a `remote_state` block with the local backend so state lives outside the unit directory. No AWS account.

## Goal

From `start/dev` and from `start/prod`, make this succeed:

```bash
terragrunt run plan
```

Each plan adds three resources. Dev state is `state/dev/terraform.tfstate`. Prod state is `state/prod/terraform.tfstate`. Both paths sit next to `root.hcl`, outside the unit directory and outside `.terragrunt-cache`. Deleting the cache leaves `terragrunt output` working.

## Where state goes by default

With no `remote_state` block, Terraform writes state inside the working copy Terragrunt builds under `.terragrunt-cache`. That directory is a download cache. Removing it removes the state with it.

`remote_state` tells Terragrunt two things:

| Argument | Role |
| --- | --- |
| `backend` | The Terraform backend name. This lecture uses `local` |
| `config` | The backend arguments. `local` takes `path` |
| `generate` | Writes `backend.tf` into the working copy before init |

`generate.if_exists = "overwrite_terragrunt"` replaces the file when Terragrunt generated it. The generated file starts with `# Generated by Terragrunt`.

A relative `path` is resolved from the working copy inside `.terragrunt-cache`, so the state file would land in the cache again. `get_parent_terragrunt_dir()` returns the absolute directory of `root.hcl`. `path_relative_to_include()` returns `dev` or `prod`, so the two units do not share a file.

## Layout

```text
start/
  root.hcl                 # terraform_binary and remote_state
  modules/record/
  dev/terragrunt.hcl
  prod/terragrunt.hcl
  state/                   # created on apply, gitignored
    dev/terraform.tfstate
    prod/terraform.tfstate
```

`root.hcl` is a parent. Terragrunt runs a directory as a unit only when that directory contains `terragrunt.hcl`.

## Steps

1. Install the pinned CLIs if you have not (lecture 02.1). `terraform_binary = "terraform"` in `root.hcl` keeps the engine on Terraform 1.17 when `tofu` is on `PATH`. The units do not set `terraform_binary`.
2. Replace the TODO in `start/root.hcl` with:

```hcl
path = "${get_parent_terragrunt_dir()}/state/${path_relative_to_include()}/terraform.tfstate"
```

Leave the `generate` block as it is. Keep `backend = "local"`.

3. From `start/dev`, then from `start/prod`:

```bash
terragrunt run -- version
terragrunt render
terragrunt run plan
```

The version line is Terraform 1.17.x. The render shows `backend = "local"` and a `path` that ends in `state/dev/terraform.tfstate` or `state/prod/terraform.tfstate`. Each plan is `Plan: 3 to add, 0 to change, 0 to destroy.`

4. Apply dev, find the state file, delete the cache, and read the output:

```bash
terragrunt --non-interactive run -- apply -auto-approve -input=false
find ../state -name terraform.tfstate
find .terragrunt-cache -name backend.tf
rm -rf .terragrunt-cache
terragrunt output
```

`backend.tf` is in the cache and contains `backend "local"` plus the absolute path. The state file remains at `start/state/dev/terraform.tfstate` after the cache is gone. `environment` is `dev`, `prefix` is `dev-lab`, `note` is `local remote state`, and `name` is `dev-lab-<word>-<word>`.

5. Repeat the apply for prod. `start/state/prod/terraform.tfstate` is a second file. Dev's file still records `dev-lab`.

The lock file next to each unit pins `local` 2.9.1, `null` 3.3.2, and `random` 3.9.1. The first plan in a unit downloads those providers. You do not need AWS credentials.

6. Destroy both units from their directories:

```bash
terragrunt --non-interactive run -- destroy -auto-approve -input=false
```

7. From `start/`, run:

```bash
./check.sh
```

The last line is `PASS  05.1 remote state`. The script plans, applies, removes each cache, reads outputs, checks the two state files, and destroys.

## If plan stops early

- `path = "TODO"` means the state path still needs the expression in the snippet above.
- A relative path such as `../state/terraform.tfstate` is resolved inside `.terragrunt-cache`. Use `get_parent_terragrunt_dir()` so the path is absolute.
- One shared path, with no `path_relative_to_include()`, makes prod overwrite dev's state. The path includes the unit directory name.
- `OpenTofu` from `terragrunt run -- version` means `terraform_binary` did not merge. It belongs in `root.hcl`, and each unit includes that file.
- `hcl fmt --check` fails when the alignment differs from the snippet above. From `start/`, run `terragrunt hcl fmt`, then run the checker again.

Compare your root file with [`solution/root.hcl`](solution/root.hcl). The units and the module match `start/`. What the run prints is written up in [`solution/NOTES.md`](solution/NOTES.md).
